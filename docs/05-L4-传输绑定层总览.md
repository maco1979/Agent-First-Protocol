# 05 · L4 传输绑定层（Transport Bindings）

> AFP‑v0.2 | 本层把 L1‑L3 语义映射为真实通信。**一套 AFP 服务可同时暴露多种绑定**，Agent 按需选择。

---

## 1. 绑定类型

| 编号 | 绑定 | 载体 | 适用场景 | 文档 |
|---|---|---|---|---|
| B-HTTP | HTTP‑Web Binding | HTTP/1.1、HTTPS | 跨网络、跨机器、互联网服务 | `06-HTTP-Web-Binding.md` |
| B-MCP | MCP Binding | MCP 协议（stdio/SSE） | 接入 MCP 智能体生态 | `07-MCP-Binding.md` |
| B-IPC | Local‑IPC Binding | Unix‑socket / 命名管道 | 本机高性能调用，无 HTTP 开销 | `08-Local-IPC-Binding.md` |
| B-SERIAL | Embedded‑Serial Binding | 串口帧 | 嵌入式硬件端点 | `09-Embedded-Serial-Binding.md` |

---

## 2. 选择矩阵

| 需求 | 推荐绑定 |
|---|---|
| 互联网/局域网服务 | HTTP |
| 接入 OpenClaw / MCP Agent | MCP |
| 本机守护进程高频调用 | Local‑IPC |
| 单片机 / 嵌入式设备 | Serial |

> 建议：一个服务同时暴露 `HTTP + MCP`；本机部署再叠加 `Local‑IPC` 提升性能。

---

## 3. 多绑定共存示例

```text
┌──────────────────────────────────────────┐
│             AFP 端点（同一服务）           │
│                                          │
│  HTTP   :47100  /.well-known/agent-...   │
│  MCP    :47101  /mcp  (SSE)              │
│  IPC    :/tmp/afp-service.sock           │
└──────────────────────────────────────────┘
```

---

## 4. 绑定一致性要求

1. 所有绑定对同一 `lookup` 返回**完全相同的 Entity 内容**（仅 meta.trace_id 可不同）。
2. 所有绑定使用同一套 error_code 枚举与 warnings 语义。
3. 所有绑定对同一 sha256 解析到同一物理资源。

---

## 5. 绑定实现最小义务

每个绑定实现必须至少支持：
- `discover()`（返回一致元数据）
- `lookup()`（返回 Entity / AFPError）
- `blob_resolve()`（若声明了 blob_access）

`list` 与 `fetch_external` 为可选，未支持时返回 `capability_not_supported`。
