# 10 · 合规实现检查清单（Compliance Checklist）

> AFP‑v0.2 | 判断一个服务是否为「AFP 兼容端点」的验收标准。分「最小合规」与「完整合规」两级。

---

## 1. 最小合规（必选，实现 AFP 端点的最低门槛）

- [ ] `discover()` 可调用，返回合法 `agent-protocol` 元数据
  - [ ] `protocol` 字段恒等于 `Agent-First-Protocol`
  - [ ] `protocol_version` 正确
  - [ ] `capabilities`、`domains` 非空且语义准确
- [ ] `lookup()` 可调用，返回标准 `Entity` 对象
  - [ ] 支持 `found` / `miss` / `partial-match` 三种状态
  - [ ] `partial-match` 时 `warnings` 非空
  - [ ] `Entity` 包含 `entity_id`、`domain`、`payload`、`meta.trace_id`、`meta.timestamp`
- [ ] `blob_resolve()` 可调用（若声明了 `blob_access`）
  - [ ] 以 sha256 内容寻址
  - [ ] 返回 locator 集合
- [ ] 统一错误对象：所有失败返回 `AFPError`，含 `error_code` + `trace_id`
- [ ] `human_view` 存在时，Agent 业务逻辑不依赖 HTML 页面
- [ ] 不使用 Cookie/Session 鉴权体系

> 满足以上即可称「AFP 兼容端点」。**不需要实现 `list`、不需要 `remote_fetch`。**

---

## 2. 完整合规（推荐生产环境）

- [ ] 实现 `list()` 分页
- [ ] 实现 `fetch_external()`（回源），且回源对 Agent 透明
- [ ] 回源限速：只处理被请求实体，禁止全站爬取
- [ ] 回源黑名单域名配置
- [ ] 限流配置（429 + retry_after_sec）
- [ ] 审计日志：trace_id、调用方、查询 key、回源耗时
- [ ] 多绑定共存：HTTP + MCP（+ 可选 IPC）
- [ ] Blob 响应头携带 `X-Blob-Sha256`
- [ ] 提供 `/llms.txt` 索引
- [ ] 版本修订支持：同一 entity_id 多 revision 并存，不覆盖

---

## 3. 验证矩阵

| 验证项 | 方法 | 预期 |
|---|---|---|
| discover 合法 | 解析返回 JSON 并对 Schema 校验 | 通过 |
| lookup found | 查询已知 key | Entity，warnings 空 |
| lookup miss | 查询不存在 key | AFPError(entity_missing) |
| lookup partial | 查询模糊 key | Entity + 非空 warnings |
| blob 完整性 | 下载后重算 sha256 比对 `X-Blob-Sha256` | 一致 |
| 限流 | 超频请求 | 429 + retry_after_sec |
| 鉴权 | 错误/缺失密钥 | 401 + auth_failed |
| trace_id | 发起带 trace_id 请求 | 响应原样回传 |
| 多绑定一致性 | HTTP 与 MCP 同 key | 实体内容一致 |
