# 01 · 协议核心（Protocol Core）

> AFP‑v0.2 | 本文件定义协议最顶层：设计原则、四层架构总览、硬性约束。所有绑定实现必须遵守本文。

---

## 1. 顶层设计原则（强制）

1. **实体优先，载体无关**
   业务交互核心是 `Entity` 实体对象与 `Blob` 二进制抽象，不绑定任何传输。同一套语义可映射到 HTTP、MCP、IPC、串口。

2. **强制自发现**
   Agent 连接端点后**第一步**执行 `discover()`，自动获取协议版本、能力集、业务域、鉴权方式、Blob 访问方式。禁止硬编码接口地址。

3. **禁止 DOM/HTML 承载业务数据**
   HTML 页面仅用于人类浏览。Agent 不得解析 HTML 提取实体、参数、业务字段。`human_view` 只是元信息标记，不是业务通道。

4. **全局内容寻址**
   所有不可变二进制资源统一以 **SHA‑256** 为唯一身份，跨存储、跨传输保持不变。

5. **可观测可审计**
   `trace_id` 全链路强制携带；实体必须携带溯源字段 `source_origin`。

6. **回源可选，Agent 透明**
   `fetch_external` 为可选 capability。开启时，抓取、清洗、抽取、缓存全部封装在端点内部，Agent 感知不到外网对抗。最小合规实现不需要外网能力。

---

## 2. 四层协议架构

```text
┌─────────────────────────────────────────────┐
│ L1  实体数据模型层（强制）                    │
│     Entity / Blob / 统一错误 / 状态枚举       │  ← 与传输完全无关
├─────────────────────────────────────────────┤
│ L2  能力自发现层（强制）                      │
│     discover() → agent-protocol 元数据        │  ← 入口随载体不同
├─────────────────────────────────────────────┤
│ L3  操作原语层（强制）                        │
│     discover / lookup / list / blob_resolve  │  ← 逻辑语义固定
│     / fetch_external(可选)                   │
├─────────────────────────────────────────────┤
│ L4  传输绑定层（可选实现）                    │
│     HTTP‑Web / MCP / Local‑IPC / Serial      │  ← 真实通信映射
└─────────────────────────────────────────────┘
```

### 各层职责边界

| 层 | 是否强制 | 职责 | 是否依赖传输 |
|---|---|---|---|
| L1 实体模型 | 强制 | 数据形状、语义、枚举 | 否 |
| L2 自发现 | 强制 | 能力、域、鉴权、资源访问方式声明 | 入口位置随载体，输出一致 |
| L3 操作原语 | 强制 | 逻辑操作语义 | 否 |
| L4 传输绑定 | 可选 | 把语义映射为真实通信 | 是 |

---

## 3. 硬性约束条款（任何实现不得违背）

1. 协议本体与传输无关；URL、Header 属于 HTTP 绑定层产物，不是 AFP 核心。
2. Blob 二进制资源强制 SHA‑256 内容寻址。
3. `trace_id` 全链路必须携带，用于审计排查。
4. `partial-match` 结果必须透传 `warnings`，上层 Agent 不得静默使用。
5. `remote_fetch`（回源）为可选能力；最小合规实现仅需本地实体查询。
6. Agent 禁止从 `human_view` 对应页面提取业务实体数据。
7. 鉴权不使用 Cookie/Session 会话体系（机器无浏览器会话概念）。
8. 业务错误禁止包装在 `200 OK` 中返回；必须使用统一错误对象与语义化状态。

---

## 4. 与周边技术的关系

| 技术 | 定位 | 与 AFP 关系 |
|---|---|---|
| MCP | 工具调用传输层 | MCP 可作为 AFP 的传输绑定；AFP 在其上定义实体业务语义 |
| REST‑API | HTTP 接口设计风格 | REST‑HTTP 只是 AFP 众多绑定之一 |
| OpenAPI | HTTP 接口描述 Schema | 用于描述 AFP 的 HTTP‑Binding 部分，不是协议本体 |
| gRPC / tRPC | RPC 框架 | 可作为 AFP 的潜在传输绑定实现，不冲突 |

## 5. 设计决策记录（ADR）

- **ADR‑001**：为什么用 SHA‑256 而非 URL 作资源身份？—— URL 会随部署变化，哈希是内容本身属性，可跨环境、跨缓存复用。
- **ADR‑002**：为什么禁止 HTML 作为业务源？—— HTML 布局易变、含噪声，解析脆且被反爬针对；结构化实体稳定可校验。
- **ADR‑003**：为什么 self-discovery 强制而非约定文档？—— 约定文档会漂移过期；运行时自发现保证 Agent 永远拿到端点当前真实能力。
