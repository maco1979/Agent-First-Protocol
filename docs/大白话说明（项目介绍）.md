# AFP 项目大白话说明（对外介绍版）

> Agent-First-Protocol | 面向任何 AI Agent 的通用服务交互标准
> 配套：协议文档族 01–11 ｜ 参考实现 `afp_service/` ｜ 测试 `tests/`（108 项全绿）

---

## 一、解决什么问题

现在各种各样对外的接口、服务五花八门：查文档、查数据库、硬件传感器、CAD 模型、业务数据、知识库、第三方能力。

**现状**：

- 每一个服务说话的规矩都不一样。AI Agent 想用它，就要专门写一份适配胶水代码。
- 有的走 HTTP 接口，有的走 MCP，有的是本地程序，有的是硬件串口。返回格式各搞各的，报错信息五花八门。
- 甚至很多服务本来就是给人看的网页，AI 还要去扒网页内容，网页一改直接崩。

**AFP（Agent-First-Protocol）就是定一套通用"普通话"标准。**

不管是什么服务：查芯片、查法律条文、读传感器读数、拿 3D 模型、查图书资料、数据库查询，随便什么业务。
不管怎么连线：网页 HTTP、MCP 工具调用、本机进程通信、硬件串口。
里面业务内容说的话全部同一套规矩，底层传输渠道随便换。

## 二、五条核心规矩

1. **先自我介绍**：AI 连上任意一个服务，先问"你能干什么"。服务返回标准的能力清单（discover），不用硬记地址、不用死记接口。
2. **只给结构化数据**：服务直接返回规整的结构化数据，不给 AI 扔网页 HTML。人想看页面可以附带做，仅供人看，AI 不去解析网页。
3. **文件用哈希指纹**：文件、二进制资料用 sha256 指纹标识。文件放哪里无所谓，指纹对得上就是同一个，还能防篡改。
4. **报错全统一**：错误码、警告、排查追踪号（trace_id），全部统一格式。不管远程网络调用还是本机调用，AI 处理错误的代码不用改。
5. **脏活服务自己扛**：如果这个服务需要去外面网上拿数据（爬虫、验证码这些麻烦事），服务自己内部搞定，AI 完全感知不到。
   - 注意：回源（fetch_external）是**可选能力**，不是每个服务都必须有。没有照样合规，只是能力声明里不许虚报。

## 三、两条"防 AI 犯错"铁律

这是 "Agent-First" 名字的真正由来——一切设计围绕"别让 AI 犯错"，而不是迁就服务端实现方便：

- **查不到就老实说查不到**：miss 返回明确错误（entity_missing），禁止包在 200 里装成功。
- **模糊命中必须带警告**：partial-match 返回结果的同时强制携带 warnings，禁止静默糊弄，防止 AI 一本正经地胡编。

另外还有一条配套原则：**能力声明必须诚实**——discover 里声明的能力必须是真实实现了的，宁可说没有，不许虚报。

## 四、核心变化

以前：AI 要去迁就每一个乱七八糟的外部服务，每个都要写特殊适配。

有 AFP 标准之后：所有对外服务统一说这套"普通话"。AI 不用改代码，接上就能直接用。

不限于芯片 datasheet，这是面向任意外部接口、任意实体资源的通用交互标准。以后不管什么知识库、硬件服务、业务系统，只要遵守 AFP，任何 AI Agent 插上即用，消灭海量重复胶水适配代码。

## 五、四层架构（服务大厅比喻）

| 层 | 名字 | 干什么的 |
|---|---|---|
| L1 | 实体数据模型 | 规定"回执单"长什么样：查到给 Entity，查不到给统一错误单（8 种错误码，不许自由发挥） |
| L2 | 能力自发现 | 门口的"自我介绍牌子"：访问 `/.well-known/agent-protocol.json` 就知道对方是谁、能干什么 |
| L3 | 操作原语 | 5 个固定动词：discover / lookup / list / blob_resolve / fetch |
| L4 | 传输绑定 | 同一套话用多种"方言"说：HTTP（网络）、MCP（AI 工具生态）、命名管道（本机）、串口（嵌入式） |

## 六、本仓库有什么

| 内容 | 位置 | 说明 |
|---|---|---|
| 协议标准 | `01-` ~ `11-` 文档 | 规矩本身（协议正文，勿改动） |
| 服务端参考实现 | `afp_service/` | 照标准做的可运行样板（HTTP + MCP + IPC 三绑定，SQLite 存储） |
| Agent 客户端 SDK | `afp_client/` | 给 AI 用的调用库（能力校验、哈希校验、警告强制暴露） |
| 测试 | `tests/` | 108 项测试验证实现确实守规矩 |
| 合规声明 | `COMPLIANCE.txt` | FULL(除回源)，Bindings: HTTP+MCP+IPC |

**启动方式**：

```bash
# HTTP 服务（端口 47100）
cd afp_service && python -m uvicorn server:app --port 47100

# MCP 绑定
cd afp_service && python mcp_binding.py

# 本机 IPC（Windows 命名管道）
cd afp_service && python ipc_binding.py

# 跑全部测试
python -m pytest tests -v
```

**详细文档导航**见 `AFP-README（协议总览与文档导航）.md`。
